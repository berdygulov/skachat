Универсальный процесс написания текста для страницы (бренд /bukmekery/[brand]/, хаб /bukmekery/, категорийный хаб /bukmekery/[категория]/ и т.д.) — четыре шага строго по порядку: подготовка → подбор ключей-кандидатов → проверка ключей в Ahrefs → написание текста

Для любого серфинга в интернете (заход на сайты букмекеров/конкурентов, поиск доп. инфы) — пользоваться расширением Claude в Chrome, оно уже установлено.

Шаг 1. Подготовка (сделать до подбора ключей)
- Список брендов/букмекеров (spisok-bukmekerov.md) и конкурентов (seo-konkurenty.md) — зайти на их сайты + поискать доп. инфу в сети

Шаг 2. Подбор ключей-кандидатов (сделать после подготовки и до проверки в Ahrefs)
- Проанализировать конкурентов по их сайтам + доп. анализ букмекеров по хабам — готовые примеры такого разбора см. в tekst/bukmekery/kategorii/
- Подобрать SEO-ключи-кандидаты с корректным интентом под Google + связанные LSI-ключи
- Обосновать выбор каждого ключа/LSI, дать рекомендации по внедрению
- Ключи-кандидаты поместить в head-klyuchi.txt в папке соответствующей страницы в tekst/ (например tekst/bukmekery/brendy/[brand]/head-klyuchi.txt для карточки бренда, tekst/bukmekery/head-klyuchi.txt для хаба-каталога). Если папки для страницы в tekst/ ещё нет — создать её (имя в транслитерации cyr-to-lat, структура папок — по finalnaya-struktura-skachat-bet.md). Сам .md файл страницы на этом шаге не трогаем — он целиком создаётся позже, в шаге 4

Шаг 3. Проверка ключей в Ahrefs (сделать после подбора кандидатов и до написания текста)
- Частоту и KD ключей-кандидатов в Ahrefs (гео: uz) проверяю и выгружаю я сама вручную — это не автоматический шаг
- Когда готово, я кидаю в промпте ссылку на выгрузку и прошу в целом прокомментировать показатели по ключам из выгрузки (объём, KD и т.д.)
- После объяснения: если меня всё устраивает — добавить эту ссылку и данные (объём/KD по каждому ключу) в head-klyuchi.txt — это и есть финальный проверенный список ключей, готовый для текста. Если не устраивает — начинаем заново с шага 2

Шаг 4. Написание текста (только после того, как я подтвердил(а) проверенные в Ahrefs ключи из шага 3 — текст пишется сразу под готовые проверенные ключи, отдельной оптимизации текста под ключи постфактум не требуется)
- Весь .md файл страницы создаётся целиком на этом шаге: блок «0. SEO-мета» (title / meta description / H1 с обоснованием — на основе разведки конкурентов из шага 2 и утверждённых ключей из шага 3, плюс таблица «Ключи, использованные в тексте» внизу блока) и основной текст (блоки 1, 2, 3... по брифу), сразу написанный под эти ключи. Формат блока 0 — по образцу tekst/bukmekery/bukmekery.md
- Формат файла: .md, имя в транслитерации cyr-to-lat
- Путь: файл кладётся в ту же папку в tekst/, что уже создана в шаге 2 для head-klyuchi.txt этой страницы. Структура папок в tekst/ формируется исходя из структуры страниц сайта в finalnaya-struktura-skachat-bet.md — каждой странице из этой карты сайта соответствует своя папка/подпапка в tekst/. Примеры: tekst/bukmekery/brendy/[brand]/bukmeker-[brand].md для карточки бренда, tekst/bukmekery/bukmekery.md для хаба-каталога, tekst/bukmekery/kategorii/[категория]/[категория].md для категорийного хаба
- Тексты пишутся по опорным пунктам брифа (kontent-brif-skachat-bet.md) под структуру finalnaya-struktura-skachat-bet — проанализировать уже готовые файлы (например glavnaja-stranica.md), чтобы понять принцип построения структуры/текстов
- Опорные пункты смотреть в бриф
  - указывать все пункты из брифа по порядку, включая те, для которых текст не пишется (например "сетка всех карточек брендов") — оставлять как пустую позицию с пояснением, а не пропускать молча
  - сохранять ту же последовательность/нумерацию, что и в брифе — номер блока в файле должен совпадать с номером пункта в брифе, чтобы избежать путаницы
- Готовый текст также поместить в tekst-dlya-publikacii.txt в той же папке — чистый текст без markdown, блоков-данных и UI-элементов, готовый для копипаста в CMS. Формат — по образцу tekst/glavnaja-stranica/tekst-dlya-publikacii.txt
